# Personal Microsoft account and Azure setup

## Purpose

RelayDrop uses Microsoft Authentication Library in the browser and Microsoft Graph delegated access. It does not require a client secret, server application, database, or Azure Storage account.

The initial deployment supports personal Microsoft accounts only.

## Create the application registration

1. Open the Microsoft Entra admin center or Azure portal.
2. Go to App registrations.
3. Select New registration.
4. Name the application RelayDrop.
5. Select Personal Microsoft accounts only as the supported account type.
6. Complete the registration.
7. Copy the Application client ID.

Do not create a client secret. A browser PWA cannot safely hold one.

## Configure SPA authentication

Use a separate registration for local development and for your production
deployment. Add localhost callbacks only to the development registration; the
published RelayDrop registration uses HTTPS callbacks only. Different client
IDs have different OneDrive App Folders, so development data stays separate.

In the application registration:

1. Open Authentication.
2. Add a platform.
3. Select Single-page application.
4. For a development registration, add the local redirect URIs:

       http://localhost:5173
       http://localhost:5173/auth/silent.html

5. For a production registration, add the final HTTPS deployment origin and its silent callback:

       https://example.com
       https://example.com/auth/silent.html

6. Keep implicit grant options disabled. MSAL uses Authorization Code flow with PKCE.

Redirect URIs must exactly match RelayDrop's origin. The minimal `auth/silent.html` page lets MSAL reuse an existing Microsoft web session without loading the full application inside its hidden iframe.

## Configure the Edge extension redirect

After building and loading the unpacked extension, Edge shows an extension ID. Add this exact URI to the same Single-page application platform without removing the web URIs:

    https://<extension-id>.chromiumapp.org/oauth2

The URI is generated by `chrome.identity.getRedirectURL("oauth2")`. It is a browser-controlled virtual callback, so it does not require DNS or hosting. The unpacked developer ID and the final Edge Add-ons ID may differ; register both when the production ID is known.

## Configure Microsoft Graph permission

Under API permissions:

1. Add a permission.
2. Select Microsoft Graph.
3. Select Delegated permissions.
4. Add Files.ReadWrite.AppFolder.

This scope limits RelayDrop to the application folder created for it in the signed-in user's OneDrive. RelayDrop does not request Files.ReadWrite or Files.ReadWrite.All.

The side panel can read the App Folder drive item's `size` and `webUrl` through the same Files.ReadWrite.AppFolder grant. RelayDrop uses those fields to show how much space its own folder occupies and to open that folder in OneDrive. It does not query the signed-in account's complete OneDrive quota: `/me/drive` quota access requires the broader Files.Read permission, which is intentionally not requested.

The first successful app-folder request creates a path similar to:

    OneDrive/Apps/RelayDrop

## Configure the local application

Copy the example environment file:

    cp .env.example .env.local

Set:

    VITE_RELAYDROP_MODE=onedrive
    VITE_MICROSOFT_CLIENT_ID=<application-client-id>
    VITE_MICROSOFT_AUTHORITY=https://login.microsoftonline.com/consumers
    VITE_RELAYDROP_WEB_URL=https://relaydrop.example

The local environment file is ignored by Git and must not be committed.

`VITE_RELAYDROP_WEB_URL` is embedded only in the browser-extension build and powers its phone setup card. It is a public destination by design; use the final custom domain when available instead of exposing a temporary host name.

Start RelayDrop:

    pnpm dev

Open http://localhost:5173, select Continue with Microsoft, and consent to the app-folder permission.

For the side-panel build and sideload flow, see [EDGE_EXTENSION.md](EDGE_EXTENSION.md).

## Validate the integration

After sign-in:

1. Press Refresh.
2. Confirm the RelayDrop app folder is created in OneDrive.
3. Send a text note.
4. Refresh in another browser session signed into the same Microsoft account.
5. Send a small file in the other direction.
6. Download and delete it.
7. Confirm RelayDrop cannot list files outside its app folder.
8. In the Edge side panel, confirm the OneDrive card reports RelayDrop App Folder usage and opens the same folder in OneDrive.

Live validation should also cover:

- expired sessions and redirect recovery
- browser refresh during authentication
- OneDrive quota errors
- throttling
- duplicate send retries
- externally deleted app folders
- file names containing OneDrive-reserved characters

## Production hosting

RelayDrop is deployed on the Azure Static Web Apps Free plan:

    https://relaydrop.example

Deployment settings:

- build command: pnpm build
- output directory: dist
- workflow: .github/workflows/deploy.yml
- the production client ID is supplied through the `VITE_MICROSOFT_CLIENT_ID`
  GitHub Actions secret; as with every browser OAuth client, the identifier is
  still visible in the built application and must never be treated as a secret
- Azure deployment token is stored only in the GitHub Actions secret AZURE_STATIC_WEB_APPS_API_TOKEN
- the production origin is registered as an allowed SPA redirect URI
- the production `/auth/silent.html` URL is registered as an allowed SPA redirect URI

Every push to main runs tests, builds the PWA, and deploys the result.

Environment values prefixed with VITE are embedded into the client bundle. Only public configuration belongs there. Never place secrets or tokens in a VITE variable.
